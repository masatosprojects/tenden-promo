Current Research Snapshot

現在のTENDENと、研究データの読み方

2026年8月29日時点。提出資料で確認できる範囲を基準に、アプリの現在地と過去の検証世代を分けて記録しています。

01

現在のアプリ

30言語・697表示項目、2つの経路候補、54避難先、BASE条件3試行平均の60秒刻み混雑データを接続した実験的Webアプリです。フル機能は鎌倉モデル地区に限定されます。

02

2つの経路計算

一般向けは400エピソード学習した線形Q学習の基準方策を参照し、要配慮者向けは勾配・道幅をコスト化した多源ダイクストラ法を使用します。要配慮者経路に強化学習は採用していません。

03

三つの研究世代

70,265人は最終の人口設定、62,299人・25条件・242試行は先行する感度分析、19,978人はTENDEN行動規則の検証です。異なる母集団の数値を同一結果として合算していません。

04

検証範囲と限界

混雑表示はリアルタイム観測ではなく事前計算です。経路の現地安全性、通信断を含む完全オフライン、P2P警報から画面遷移までの本番相当E2E、母語話者による30言語の意味検証は未完了です。

安全上の位置づけ
本アプリは避難判断を代行せず、安全を保証しません。候補の比較表示であり、道路閉塞・工事・現地の混雑・津波の状況を確認した案内ではありません。取得失敗時の簡易線表示も、道路通行を確認した経路ではなく参考表示です。

Evacuation Philosophy

「各自で判断し避難する」という基本方針

津波てんでんこ

三陸沿岸部に伝わる、迅速な主体避難を促す防災教育の知見

「津波襲来時には、周囲の状況を注視しつつ、
各自が迅速に安全な高台を目指すこと」

「てんでんこ」とは、避難者が他者の行動に同調しすぎず、それぞれが自ら迅速に安全な場所を目指すことで、地域全体の避難成功率を高めるという防災の知見です。

TENDENは「各自が主体的に動く」という側面に着想を得ています。ただし伝承そのものと同一ではありません。端末ごとの疑似乱数で候補を分散し、一般向けの強化学習ルートと要配慮者向けルートを比較表示します。

Research Insight

Tourists evacuation analysis

避難経路への一時的な集中現象

0
kamakura-simで観測された、地域住民と一般来訪者（観光客）の避難完了率の差

地理感覚や避難経路情報の少ない一般来訪者は、モデル上、避難開始や経路選択で不利になる傾向がありました。これは人を対象にした実地効果検証ではなく、設定した行動規則の下で得られたシミュレーション結果です。

また、特定経路に多数が集中する条件では、狭い道路や交差点に滞留が生じました。経路分散はこの集中を緩和する設計仮説ですが、導入率に応じて混雑が常に単調に減るとは2回の検証では確認できていません。

The Solution

Autonomous Route Diversification

避難経路の選択における
自律的な分散効果

2本のルート — 一般向けの強化学習ルートと、勾配・道幅に配慮した要配慮者ルートを同じ画面で比較します。初期状態で一方を自動選択せず、利用者が選びます。

Route Architecture

Two core routes

強化学習AIが提案する最適避難経路と、要配慮者への配慮ルート

TENDENは道路網データに沿う経路候補を明瞭なラインで表示します。ただし、取得失敗時の簡易線表示は道路通行を確認した案内ではありません。

● AIモデル推奨ルート
● 要配慮者ルート（緩やか）
●

AIモデル推奨ルート (強化学習)

kamakura-simの道路網上で7特徴量を用い、400エピソード学習した線形Q学習の基準方策を参照します。BASE条件3試行平均の混雑推移に応じて限定的に候補を差し替え、端末ごとの疑似乱数で分散します。現地での安全・到達を保証するものではありません。

●

要配慮者ルート (坂道配慮・緩やか)

勾配と道幅をコストに組み込んだ多源ダイクストラ法で、複数の安全地点から逆向きに方策を計算します。強化学習案は急坂回避に失敗したため採用せず、説明可能な決定論的手法へ置き換えた経緯があります。

Support Functions

12 research-backed functions

避難行動をサポートするための
12の機能設計

01

AIモデル推奨ルート

400エピソード学習した線形Q学習の基準方策を参照し、一般向け候補を提示します。端末ごとの疑似乱数で経路を分散する設計ですが、実社会での効果・安全性は未検証です。要配慮者向けは別方式の多源ダイクストラ法です。

02

多言語音声ガイダンス

Web Speech APIを活用し、歩行中の画面凝視を抑制するための音声ガイダンスを搭載。端末言語に連動した音声読み上げで安全な避難を支援します。

03

スマートコンパス連動

スマートフォンの内蔵センサーと同期し、マップ上に進行方向を進行コーンとして投影。現在地ピンと連動してリアルタイムに向きを追従します。

04

ハザードローカル判定

GPS座標と取得済みの浸水想定データを用いて現在地を判定し、海岸・河川近傍、低地、内陸方向の条件から候補を絞ります。到着時の再検証や現地安全確認は未実装です。

05

オフライン動作設計

Service Workerは利用者が設定から有効にするオプトイン方式です。主要ファイルと閲覧済み地図をキャッシュしますが、OSRM・標高API・P2P警報・未取得地図などは通信が必要で、完全オフライン動作は未検証です。

06

避難所容量の考慮

54施設の避難先データと事前計算した混雑情報を参照します。実際の収容状況や道路閉塞をリアルタイムに監視する機能ではありません。

07

ルート逸脱アラート

ハザードエリアへの進入や案内ルートからの大幅な逸脱（100m以上）を検知した際、OS標準の通知やアラート音で即座にフィードバックします。

08

スリープ防止 (Wake Lock)

ブラウザのスリープ防止APIを有効化し、移動中の画面消灯をブロック。スマートフォンの画面をONに保ち、GPSの測位と画面表示を継続します。

09

直感的なサイドラベル表示

マップ上の操作に多言語ラベルを表示し、30言語の辞書と連動します。表示構造は8つの端末・ブラウザ条件で確認しましたが、全機能の組合せ試験と母語話者による意味検証は未完了です。

10

津波避難3原則ガイド

「即時避難」「垂直避難」「戻り禁止」といった津波防災の基本原則をイラストとテキストで解説。事前の学習や被災時の行動確認に役立ちます。

11

地震警報のリアルタイム監視

P2P地震情報のWebSocketへ接続し、切断時は再接続します。最新イベントを選ぶ修正も行っていますが、実際の警報受信から緊急画面遷移までの本番相当E2E試験は未完了です。

12

ローカルプライバシー処理

位置情報は、標高取得（国土地理院API）・避難ルート計算（OSRM）・ハザード判定（国土地理院タイル）のためにそれぞれの公開サービスへ送信されますが、ユーザーを特定する情報の保存や第三者提供は行いません。安否共有（Web Share API）も、ユーザーが明示的に操作した場合のみ送信されます。

Technology Core

Web Technologies For Disasters

被災時における安定した自律アルゴリズムの適用

Canvas APIによる津波浸水想定区域のローカル判定

国土地理院が配信する広域津波ハザードマップの画像をメモリ上のCanvas領域に読み込み、現在地のGPS座標に対応するピクセルのカラーデータ（RGBA値）を判定。外部サーバーとの往復通信を行わず、浸水想定域への進入を端末ローカルで即座に検知する設計です。

取得済みデータが端末に残っている場合はローカル判定に利用できます。ただし、未取得データや外部APIを含む完全な通信断環境での一連の動作は検証していません。

電波障害を想定したオフライン重心判定

最寄りの沿岸重心座標との距離から対象地域を切り替える設計を導入しています。これは参照先を選ぶ補助処理であり、オフライン時の避難所検索・経路選択の信頼性を保証するものではありません。

GPS座標ピクセルのカラー値RGBAをローカル解析し警告バッジを自動描画

スマートフォンにおける5つの主要なWeb標準技術（API）の連携仕様

Screen Wake Lock API

画面の自動消灯を防止し、バックグラウンド移行によるGPS測位の途絶を防ぎ、継続的なナビゲーションを維持します。

Vibration API

歩行中の揺れや画面を直視できない状況を想定し、ルート逸脱や危険エリア進入時に固有の振動パターンで警告を伝えます。

Notifications API

アプリ非アクティブ時でも、危険判定時にOS標準のプッシュ通知を発行。過度な電池消費を防ぐ表示制御機能を備えます。

Device Orientation API

スマートフォンの内蔵センサーとリアルタイムで同期し、避難者の向きをマップ上のコーン状の視覚効果として投影します。

Battery Status API

バッテリー残量の低下を検知した際、GPSの測定頻度を調整するなどのアラートを表示し、避難完了までの電源維持をサポートします。

Research Background

Evacuation Simulation Data

避難情報の共有方法に関する検証

鎌倉沿岸部・大規模人流避難シミュレーション（kamakura-sim）の先行研究世代（62,299人・25条件・242試行）と、TENDEN行動規則の別検証（19,978人）を区別して参照します。

一律に特定の経路を選択した場合

滞留の発生

モデル内では同じ規則を持つ避難者が特定経路へ集中し、狭い道路や交差点に滞留が生じる条件がありました。現実の群集事故発生率を直接予測する結果ではありません。

各自が自律して経路を分散選択した場合

スムーズな避難

19,978人のモデルで一般来訪者にTENDENの行動規則を適用した割合を0%から100%へ変えると、避難完了率は18.4%から34.9%へ上昇しました。一方、混雑ピークの単調な低下や閾値は2回の実行では確定していません。

システム設計の思想

TENDENが分散避難を組み込む理由はここにあります。
端末ごとに独立した疑似乱数で候補を分散し、一律誘導を避けることが設計上の狙いです。ただし、モデル上の「導入率」は現実の利用率や効果を意味せず、実社会で全体の生存性を最大化すると断定できません。

「kamakura-sim 共同検証データについて」
70,265人の最終人口設定、62,299人・25条件・242試行の感度分析、19,978人のTENDEN行動規則検証を、世代と用途を分けて研究サイトに記録しています。
